Networked Music Performance in Max: from Tool to Object Prototype

Poster by Rodolfo Cangiotti – hello@rodolfocangiotti.art
ADC Bristol 2026

1️⃣ Introduction

What

Abstract

Max ecosystem is currently providing a lot of tools for Networked Music Performances. However, depending on the use case and context, these available tools might be not sufficient, sometimes.

This poster will try to condense the state-of-the-art regarding Max objects for Networked Music Performance as of now. In addition, a new Max object capable of covering a more vast scope of application will be proposed.

Why

Research Objective

This work aims to demostrate that, even if Max environment already provides plenty of tools for different contexts of application, developing new objects might be a valid option. Thanks to the official Cycling ‘74 SDK, that process is definitely straightforward.

How

Research Methodology

The current state-of-the-art will be evaluated against assessment criteria, as well as the new Max object proposed.

When and Where

Research Context

This research started in 2025 as final work of the New Technologies for Performance course, at Marche Polytechnic University (Ancona, Italy), and is still ongoing.

2️⃣ State of the Art

Assessment Criteria

To evaluate the tools for Networked Music Performance currently available in the Max environment, an assessment criteria has been formalized. The following features have been used to set up a metric:

  • shared data type/s – audio signal is preferred
  • data sharing protocol – transport layer protocols are preferred
  • dependency/linkage with external tools – no dependencies is preferred

Max Native Objects

Here is a list of all the objects provided via the official Max distribution.

udpsend and udpreceive

Max objects to send and receive messages over a network.

Key points:

  • 🟢 they leverage the UDP protocol
  • 🔴 they are only for control data

To learn more:

  • udpsend object reference
  • udpreceive object reference

jit.net.send and jit.net.recv

Jitter objects to send and receive matrices over a network.

Key points:

  • 🟢 they are built upon the TCP protocol
  • 🔴 theoretically, they are only for video streams

To learn more:

  • jit.net.send object reference
  • jit.net.recv object reference

mxj and mxj~

Objects to execute Java code in Max and MSP.

Key points:

  • 🟢 they allow to use Java classes for data exchange via TCP/UDP
  • 🔴 they need JDK to be installed on host machine

To learn more:

  • mxj object reference
  • mxj~ object reference

param.osc

Max object to control and report information about Parameters via OSC.

Key points:

  • 🟢 it provides a control interface for native OSC communications between objects, via UDP protocol
  • 🔴 it allows to manage only object Parameters in Max v.9.x.x

To learn more:

  • param.osc object reference
  • Parameter mode user guide

3️⃣ Proposed Solution

Object Requirements

Considering the assessment criteria used to evaluate all the options currently available in the Max ecosystem, none of those options achieved a full score.

Then, this research has tried to propose a new Max object. This latter should:

  • allow users to share audio signals
  • allow audio contents to be shared both via UDP and TCP protocol
  • not require dependencies to be installed

In particular, the object prototype should satisfy all the following requirements as well:

  • it should allow user:
    • to set IP and port of the target device
    • to set the protocol to be used for exchanging data with the target device
    • to decide the contents to be shared with the same device
    • to connect to that target device
    • to disconnect from the same device
    • to get the object state

Development Tools

The following tools have been used to prototype the new Max object.

1. MuSNet API

This research is part of a project named MuSNet, whose objective is to create an ecosystem for Networked Music Performances, with the following key points:

  • guaranteeing cross platform compliance
  • providing builds for multiple targets
  • allowing streamlined configuration and usage

The project proposes tools to create a low latency client-server network, where users share musical contents via ad hoc defined protocol.

From technical perspective, MuSNet is written in C++ and provides a very high-level class with methods for:

  • connecting to a MuSNet session
  • sharing data with other connected users
  • disconnecting from the session

This project as been used as Networked Music Performance tool because it partially satisfies some of the object requirements previously listed via an intuitive API.

2. Min DevKit

Min DevKit is the official SDK distributed by Cycling ‘74, to speed up the development of Max objects. It is written in modern C++ and provides a well documented high-level declarative API to implement new objects.

Here are the SDK essentials:

sample_operator and vector_operator base classes

Parent class from which the main one should be inherited, respectively to implement sample-based or vector-based DSP

operator() method

Actuall class method where the signal computation algorithm should be implemented

inlet and outlet class attributes

Data types to be used in the main class to define Max object’s I/O

argument and attribute class attributes

Data types to be used in the main class to define Max object’s arguments and (named) attributes

message class attributes

Class instances to define the behavior of the Max object when receiving certain messages

setup, dspsetup, etc. magic messages

Special messages managed by the Max object under the hood; to be overwritten to customize the object behavior during particular events (like switching on/off DSP engine, etc.)

MIN_FUNCTION, MIN_ARGUMENT_FUNCTION, etc. macros

Useful tools to speed up the code writing

Implementation Process

By using the Min DevKit framework to define the object’s main features and by injecting the MuSNet API inside it, the code writing stage has been more linear than expected.

Result

The overall implementation process produced a stable beta version of the new Max object.

Evaluating it with the assessment criteria stated above, no defaults are found in the object because:

  • 🟢 it allows to use both TCP and UDP protocol to communicate with the network
  • 🟢 it lets user exchange stereo audio streams
  • 🟢 it doesn’t need any dependency to be installed to work properly

4️⃣ Conclusions

This research tried to analyze the current state-of-the-art regarding Max objects for Networked Music Performance. Despite the ecosystem already provides a variety of tools for Networked Music Performances, some lacks have been identified and a novel solution has been proposed. By using the Min DevKit together with the MuSNet API, it has been possible to prototype a new Max object, fulfilling all the requirements defined.

The work in question aims to demonstrate the endless possibilities provided by the Min DevKit to enrich Max environment. Networked Music Performances as context, together with the MuSNet project, delimit a particular study case and the same process can be definitely replicated in different contexts.
